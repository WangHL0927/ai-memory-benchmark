# 入库政策 default v1：基于明确意图的个人与项目知识

- id：`default`，版本：`v1`（2026-11-11）。机器可读版本：[default-v1.json](default-v1.json)。
- 这是一份**可选**政策，适用于“给 AI 助手用的长期记忆只收录用户或其项目的独有、可复用信息”这类场景。框架本身不要求使用它；换一份政策，评分会随之改变。

## 核心判断

删掉公共知识和网页复述后，还剩下属于用户或其项目的独有信息，而且以后会用到（理解用户、解释决策、避免重复研究、延续工作），才记。“以后可能搜得到”不算理由。不按对话轮数、篇幅或技术含量打分。

## 类别（`category`）

| 值 | 含义 | 证据要求 |
|---|---|---|
| `decision` | 用户拍板的方案。理由和放弃的选项作为它的条件（`rationale`），不另拆单元 | 引用用户原话 |
| `preference` | 用户明确说出的判断、偏好、原则 | 引用用户原话；不能从行为推断；不能把助手的意见归给用户 |
| `fact` | 独有的事实与环境：配置、部署、资源归属、项目约定、实测过的流程和坑 | 指出验证发生在哪一轮 |
| `research` | 至少两个独立来源交叉核查后得出的独有结论 | 附来源，以及冲突和局限 |

判例：

- 助手给出一个方案，用户说“就这样吧” → `decision`。用户说“对，端口是 4200” → `fact`。区别在于被确认的是一个选择，还是一个事实。
- 只查了一份官方文档得出的结论 → 不该记（`doc_restate`）；如果实测发现文档写错了 → `fact`。至少两个来源交叉核对过的 → `research`。
- “我一般都先跑测试再提交” → `preference`。只是这一次先跑了测试 → 不该记（`one_off`）。

## 属性（`attributes`）

### `basis`：意图依据

| 值 | 含义 |
|---|---|
| `explicit` | 用户明确要求记下 |
| `confirmed` | 用户确认过的决定、状态变化或纠正。必须有一个用户回合做出肯定表述；**沉默不算确认** |
| `verified` | 助手发现、并在本次会话里验证过的独有事实 |

约束：`decision` 和 `preference` 只能是 `explicit` 或 `confirmed`；`verified` 只适用于 `fact` 和 `research`。

## 不该记（`reject_reasons`）

| 码 | 含义 |
|---|---|
| `chitchat` | 闲聊 |
| `one_off` | 一次性事务，或“仅这一次”的要求 |
| `unconfirmed` | 临时猜测、未确认的选项、助手提出但用户没有确认的内容 |
| `superseded` | 会话中被推翻的旧状态或旧决定（被推翻的理由可以作为新决定的条件） |
| `general` | 通用知识、普通搜索结果 |
| `doc_restate` | 复述官方文档；实测发现文档有错或缺漏的除外，那算 `fact` |
| `news` | 新闻和强时效资讯（只在作为某个决定的当时依据时，随那个决定一起记） |
| `bare_error` | 只有报错加一份通用排查清单 |
| `other_subject` | 别人的事，或者与用户及其项目无关的事 |
| `wrong_scope` | 本身值得记，但属于另一个项目 |

## 条件类型（`condition_types`）

`scope_limit`（仅限某范围）、`temporal`（时间或版本限制）、`once_only`（仅这一次；出现这类条件时，整条通常应判为 `one_off`）、`needs_confirm`（执行前还要确认）、`action_type`（只适用于某类操作）、`rationale`（理由、放弃的选项）。

## 范围（`scope_values`）

`project:<名称>`（以 transcript 头部的 `project` 为准）、`global`（跨项目适用的规则或偏好）、`user`（用户个人的通用事实）。

## 被推翻的旧状态（`superseded`）

`final_state_only`：以会话结束时的最终状态为准，被推翻的旧状态作为负例 `superseded`。

## 附加标记（`flags`）

- `contains_secret`：提交项的正文或证据里，是否出现了凭据、token、私钥、cookie 等秘密值的原文。只写了存放位置或获取方式的不算。**本政策不把秘密值当作价值判定的依据**（记了不算误记，没记也不算漏记），这个标记只单独报告。

## 切分示例

1. “这个方案用 PG，不用 SQLite，因为要跨设备” → 1 个 `decision`；条件：`rationale`（要跨设备；放弃 SQLite）。
2. “以后提交信息都用中文，PR 描述也用中文” → 2 个 `preference`（拿掉任意一条，另一条仍然成立）。
3. “这次先别推，等我看完” → 不该记（`one_off`）。
4. 助手说“可能是缓存的问题”，用户没有回应 → 不该记（`unconfirmed`）。
5. 跑测试发现某个工具的 `--fix` 参数会改动未暂存的文件，与文档描述不符 → 1 个 `fact`（`verified`）。
6. 前半段定了用 A 方案，后半段改成 B 方案 → 1 个 `decision`（B，条件里写明放弃 A 的理由）+ 1 个负例 `superseded`（A）。

## 定向边界样本要覆盖的组合

“明确要求 / 仅本次 / 禁止保存” × “本人陈述 / 转述别人” × “当前项目 / 别的项目”，外加“会话中途改主意”。
