# 记忆摄取质量评测报告（2026-11-12）

本报告评估记忆系统的摄取质量。被测系统是接受会话并导出记忆的产品；入库政策规定哪些信息值得保留；应记单元是按政策标出的可独立使用的信息；陈述是记忆中一个可核对的事实、偏好、决定或计划。标注先确定应记单元，判定模型再通过拆分判定分别检查召回覆盖和陈述准确性。

| 项 | 内容 |
|---|---|
| 日期 | 2026-11-12 |
| 评测范围 | 单段会话的记忆摄取：漏记与误记 |
| 被测系统 | OpenViking 0.5.4.1、ai-memory 3.4.0、claude-mem 15.17.0、Basic Memory 1.0.0 + 固定 agent |
| 数据集 | HaluMem-Medium（30 段，6 个源用户）；Trace Commons（31 段，其中 18 段所有系统都已判定） |
| 判定模型 | `gpt-6.1-sol`，推理强度 low；未进行人工校准 |
| 框架 | [评测框架](../../docs/framework.md) v0.6，拆分判定协议（6.4 节） |

## 摘要

四个产品统一使用同一个 LLM，生成参数沿用产品默认。

- **HaluMem-Medium**（30 段）：漏记率为 31%–49%，其中完全没有记住的应记单元只占 4%–11%，其余为部分记住；误记率（按陈述计）为 12%–21%。
- **Trace Commons**（所有系统都已判定的 18 段 coding agent 会话）：漏记率从 6%（OpenViking）到 52%（ai-memory）；误记率为 7%–16%。
- OpenViking 在 Trace Commons 上漏记率低，来自记忆中保留的原始聊天记录，这部分占其记忆字数的 96%。只看摘要部分时，漏记率为 60%。
- claude-mem 写得最多：每段 Trace Commons 会话约 700 条陈述，输入 token 约为会话原文的 17 倍，漏记率为 16%。

## 1. 评测设置

### 1.1 数据

| 数据集 | 内容 | 固定 revision | 应记单元来源 |
|---|---|---|---|
| [HaluMem-Medium](../../datasets/halumem.json) | 多轮日常对话 | `cb04336` | 数据集自带的记忆点，按 [halumem-v1](../../policies/halumem-v1.md) 转换 |
| [Trace Commons](../../datasets/trace-commons.json) | coding agent 会话 | `112ebd4` | 模型盲标（`gpt-6.1-sol`，推理强度 high），采用 [default-v1](../../policies/default-v1.md) |

HaluMem-Medium 按样本标识排序取前 30 段，来自 6 个源用户，含 251 个应记单元。Trace Commons 长会话切分后准备了 31 段。

### 1.2 被测系统

| 系统 | 配置 | 说明 |
|---|---|---|
| OpenViking 0.5.4.1 | 官方向导对自定义 OpenAI 兼容端点写出的配置 | 温度 0.0，复现产品直连百炼时关闭思考的行为 |
| ai-memory 3.4.0 | single 整理，生成参数采用默认值 | 温度 0.2；默认不采集助手回复 |
| claude-mem 15.17.0 | `openai-compatible`，生成参数采用默认值 | 温度 0.3，单次输出上限 4096；关闭向量功能 |
| Basic Memory 1.0.0 + 固定 agent | 最小 agent，系统提示词为官方 `memory-capture` | Basic Memory 不做抽取，结果反映产品与 agent 的组合 |

所有系统使用 `deepseek-v4.1-flash-1017`。OpenViking、ai-memory、Basic Memory 使用 `qwen3.7-text-embedding`（1024 维）；claude-mem 关闭向量功能，不使用该 embedding。每次调用实际发出的参数保留在运行记录中。完整配置及源码出处见 [被测系统配置](../../docs/systems.md)。

每段会话从空记忆库开始摄取，结束后导出系统存下的全部记忆。

### 1.3 指标

- **漏记率**：应记单元中，不能从系统全部记忆中完整得出的比例。“完全未记住”包括 none 和 distorted；partial 单列为部分覆盖。
- **误记率**：无依据或写歪原意的陈述数 ÷ 陈述总数。部分有依据的陈述不进入误记分子；同一个陈述只归入一类。附带的原样会话摘录整体计 1 个陈述。

区间为 95% bootstrap 区间，重采样 10,000 次，种子为 20261112。代码按 `gold.session_id` 聚类；HaluMem 转换器把同一源用户的多个 session 映射到同一个标识，因此本批重采样单位是 **6 个源用户聚类**，不是 30 段独立会话。

## 2. 结果

### 2.1 HaluMem-Medium

#### 被测产品（按名称列示）

| 系统 | 漏记率（95% 区间） | 完全未记住 | 误记率（95% 区间） | 每段陈述数 | 每段记忆条数 |
|---|---|---|---|---|---|
| ai-memory | 49%（39%–61%） | 9% | 19%（18%–20%） | 33 | 1.0 |
| claude-mem | 47%（37%–61%） | 11% | 15%（12%–19%） | 179 | 12.1 |
| OpenViking | 41%（33%–47%） | 9% | 12%（8%–16%） | 30 | 7.5 |

#### 固定 agent 组合

| 系统 | 漏记率（95% 区间） | 完全未记住 | 误记率（95% 区间） | 每段陈述数 | 每段记忆条数 |
|---|---|---|---|---|---|
| Basic Memory + 固定 agent | 31%（24%–37%） | 4% | 21%（19%–24%） | 40 | 1.0 |

四个系统均有 30 个有效样本、251 个应记单元，未排除失败样本。部分区间重叠；本报告未计算配对显著性检验，不给出总排名。Basic Memory 的结果对应产品与固定 agent 的组合。

### 2.2 Trace Commons

所有系统都已判定的 18 段（共 340 个应记单元）：

| 系统 | 漏记率 | 完全没记住 | 误记率（按陈述） | 每段陈述数 | 每段记忆条数 |
|---|---|---|---|---|---|
| OpenViking | 6%（3%–9%） | 0.6% | 9%（6%–13%） | 85 | 12.0 |
| claude-mem | 16%（11%–22%） | 5% | 16%（13%–18%） | 696 | 64.6 |
| Basic Memory + agent | 48%（41%–53%） | 11% | 9%（6%–11%） | 84 | 1.0 |
| ai-memory | 52%（43%–60%） | 18% | 7%（5%–10%） | 78 | 1.0 |
| OpenViking（只看摘要） | 60%（52%–68%） | 19% | 10%（7%–15%） | 71 | 12.0 |

31 段中各系统的有效样本数：OpenViking 29、ai-memory 30、Basic Memory + agent 30、claude-mem 19。claude-mem 有 4 段因源会话中工具调用与结果无法配对而不能回放，另有 8 段未判定。上表只保留所有系统都有有效结果的会话，使各行覆盖相同的样本。

## 3. 观察

### 3.1 产品行为与配置

**OpenViking 附带原文。** OpenViking 在记忆文件中附上原始聊天记录。HaluMem-Medium 上，224 条记忆中有 114 条（51%）含原文摘录；Trace Commons 上，原文占其记忆字数的 96%，记忆总字数约为会话原文的 0.72 倍。只看摘要部分时，漏记率在 HaluMem-Medium 上为 49%（42%–54%），在 Trace Commons 上为 60%（52%–68%）；含原文时分别为 41% 和 6%。该对照由相同导出结果移除附带原文后重新判定，不是另一次产品运行。本批每段会话有 1 次 LLM 调用。

**OpenViking 的温度与思考开关。** 自定义 OpenAI 兼容端点的官方向导配置写入温度 0.0。产品直连百炼时按域名发送关闭思考的开关；本地代理改变了可见域名，因此配置中显式写入 `enable_thinking:false`，复现直连行为。

**ai-memory 不采集助手回复。** 默认设置为 `capture_assistant=false`。本批每段会话导出 1 页；判定结果中包含把未采集助手回复表述为“会话没有助手回复”的错误。配置与会话实际内容之间的差异会影响生成记忆。

**claude-mem 记录观察与总结。** 适配器提交工具事件和会话总结事件。本批每段平均 179 个陈述，LLM 调用次数中位数为 22。其默认 `reasoning:{enabled:false}` 没有使本评测端点关闭思考，配置说明中的服务端测量记录见 [systems.md](../../docs/systems.md)。单次输出上限为 4096。原生跳过、丢弃和输出截断记录在运行元信息中，具体原因按样本核查。

**claude-mem 的向量配置。** 产品提供的 OpenAI embedding 选项使用固定的 `text-embedding-ada-002`，无法配置为本评测指定的 qwen 模型；本报告使用关闭向量的配置，不能把结果外推到启用向量的配置。

**Basic Memory 与 agent。** Basic Memory 提供存储和检索；agent 决定写入内容。本批每段导出 1 篇笔记，该组合的漏记率点估计最低、误记率点估计最高。

### 3.2 评测口径

**部分覆盖占漏记的大部分。** 完全未记住占应记单元总数的 4%–11%；漏记率还包含记住主体但缺少关键条件或细节的 partial 单元。

**计数单位会影响误记率。** 按条口径把 `grounded=no` 或 `distorted=true` 的整条记忆计为误记。本批按条误记率为：ai-memory 90%、Basic Memory + 固定 agent 93%、OpenViking 16%、claude-mem 70%。按陈述口径为 12%–21%。陈述切分和原文摘录的合并计数仍会影响比较。

**判定约定需要一致。** 判定模型选型比较了不同的日期与“写歪”判定约定；按条误记率随约定变化，不能直接作为按陈述口径的校准结果，见 [判定模型选型](../../docs/judge-selection.md)。

## 4. 模型用量

每段会话的 LLM 用量（中位数；Trace Commons 取 18 段共同样本）：

| 系统 | 调用次数（HaluMem / Trace） | 输入 token（HaluMem / Trace） | 输入 token ÷ 原文字数 |
|---|---|---|---|
| OpenViking | 1 / 1 | 9.9K / 47.3K | 0.6 / 0.4 |
| ai-memory | 1 / 1 | 6.3K / 25.2K | 0.4 / 0.2 |
| Basic Memory + agent | 3 / 3 | 37.4K / 161.3K | 2.5 / 1.3 |
| claude-mem | 22 / 58 | 243.3K / 1,946.6K | 14.7 / 16.7 |

token 数取自本地代理的计量。claude-mem 有 1 段 Trace 会话未记录用量，不计入中位数。

## 5. 局限

- 判定未进行人工校准；陈述切分与计数的可靠性未单独验证。
- 统一 LLM 和外部 embedding、关闭 claude-mem 向量，与产品默认安装配置不同；使用各自默认模型时结果可能不同。
- 每段会话从空库开始，不涉及跨会话更新、去重、长期维护或读取质量。
- 应记单元取决于入库政策；产品不知道评测使用的政策，HaluMem 原始点也可能包含多个事实。
- 样本按标识排序选取，只有 30 段、6 个源用户聚类，不足以据此推断整个数据集的表现。

## 6. 复现

1. 按 [数据集清单](../../datasets/README.md) 下载数据，校验 revision 和 sha256。
2. 按 [README“运行一次评测”](../../README.zh-CN.md#运行一次评测) 执行转换、标注、运行被测系统、判定和评分。HaluMem 已有转换后的 gold，可跳过盲标。
3. 逐样本核对运行记录和判定记录中的模型、推理强度、提示词哈希及实际参数；报告中缺失的信息保留为“未记录”。

Trace Commons 加工产物的发布按清单中的 CC-BY-4.0、署名与脱敏要求处理。HaluMem 的清单为 `scores_only`，仅发布汇总分数与产物哈希。
