# 记忆累计库与原生读取评测 v0.8 · 基线与局限性报告 · 2026-11-19

## 这批数据能说明什么

在未用于调参的 28 段、36 题上，累计库与原生读取显示了五套产品配置在本轮的大致表现、证据从「库中有」到「送达」再到「使用」的分布，以及实际读写成本。

## 这批数据的局限

产品排名超出这批数据能支持的结论。

1. OpenViking 的 coding 仅 10/24 题可判，14 题超窗，其综合分对应可判子集，与其余产品的全题得分缺少可比性。
2. X2 和 Basic Memory + agent 这 2 套配置每场只在会话结束触发 1 次摄取，用整场内容集中整理，相对原生轮次停点触发的偏差方向未知。
3. 每套产品配置只有 1 次正式运行，每个 coding 场景计划 6 题，判词未作人工校准，综合分的 95% 项目聚类 bootstrap 区间见下表。
4. X2 使用 v0.7.3，审核读取全量转录，写入成本和摄取提示词的后续改进未进入本轮。
5. 摄取失败留在端到端结果中，HaluMem 的失败段为 X2 6/20、Basic Memory 4/20、ai-memory 2/20。
6. 固定读者 qwen4-max 每题最多调用原生工具 5 次，X2 在 36/36 题触顶，结果体现该读者的读取方式。
7. 中途修正了 Basic Memory 的 1 个 coding 域项目绑定并补跑，格式失败的判词沿原规则重判，部分产品的读侧嵌入用量不可观测。

X2 是未公开的内部系统。主测 N 衡量固定 qwen4-max 驱动各产品原生读路径的端到端表现。coding 为两个独立项目，各有四次连续写入。HaluMem 为两个独立用户，各十次连续会话。每题在期末正常可读状态启动独立读者会话。五个产品共用 24 道 coding 与 12 道 HaluMem 题。E 只覆盖事先选定的 12 道题。

统一按 o200k_base（tiktoken 0.14.0）计量 T/R，设计作答窗口为 200,000 token，实际按更小的读者端点上限 129,024 token 执行。读者使用非流式 Chat Completions，思考开关使用端点默认。题卡与金标用 gpt-6.2-sol high，判定用 gpt-6.2-sol medium。摄取用 deepseek-v4.1-flash-1017，X2 修订用 deepseek-v4-pro。
