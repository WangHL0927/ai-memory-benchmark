## 这份数据能说明什么、不能说明什么

本期评测用于发现重大问题。这份缩减版数据作为有局限的基线发布，可用来了解五个产品在本轮条件下的粗略位置、各产品写入与读取成本的量级，以及评测框架暴露的缺陷。

这份数据不足以给产品排出优劣，原因如下。

1. S1 只有 1 题，却占价值分的 25 分，例如 ai-memory 与 X2 的 25.35 分综合分差中，25.00 分来自这道题（见[单题权重诊断](#单题权重诊断)）。

## 样本与局限

本轮为框架 §8 的缩减版，共 4 段 coding 和 4 段日常对话，覆盖范围为表 1 的子集。每段 coding 冻结 3 题。每个配置和样本只评一次，小样本区间及缺项限制总体比较。HaluMem 仅作摄取诊断，两条作答基线用于 coding。区间来自按来源聚类的 10,000 次重抽（seed 20261112）。

这 8 段既用于先前的故障诊断和修订方案设计，也用于本轮复测，现属于调优集，结果可能偏乐观。

v0.7.1 主轮 17 条草案中 12 条被驳回，10 条的主因是细节无据或未确认。旧审核还在两条 HaluMem 驳回中把晚于运行日的会话日期视为未来。v0.7.2 主轮有五段摄取失败，四段 coding 均缺有效判定。这些观察描述对应版本的 X2 执行。

五个产品使用同一批冻结 transcript。本次只回放和判定 X2。其余结果与题目复核沿用 v0.7.1。正式回放前排除了端点对 JSON 关键词的阻断，试跑产生的调用与本表的正式 W 分开计量。
