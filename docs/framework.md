# 记忆摄取评测框架 v0.7.1

2026-11-19 · 定稿。本轮对 Trace Commons 启用 default-v2，对 HaluMem 使用 halumem-v1。框架规定评测方法，政策规定应记内容。表 1 的历史数字用于确定样本和调用预算。本版沿用已冻结的金标与题卡，并对齐作答截点。

**主问题有两个。** 新会话拿到上次留下的记忆，能把多少件重要的事做对？为了得到这些结果，写入时花了多少模型资源，使用时又要读多少文字？在 coding 样本上，先按场景计算价值分，再按公开汇率扣除超出参考量的读写成本，得到综合分。日常对话使用另一份入库政策，单独报告摄取质量和开销。每个失分项都应能追到一道任务、一个要素、一条错误陈述或一笔用量。

## 1　评测单位与适用边界

一个样本是一段带轮次的会话 T。每个参评配置在独立空库摄取同一 T，按产品正常流程完成写入，导出下一次会话有权使用的全部持久记忆 D。固定作答者在封闭环境中读 D 完成任务。结果适用于这个作答者、这个导出阶段和这批样本。产品原生搜索、分块召回策略、长期多会话维护、真实在线增量开销均需各自的实验。

**公开主轮按产品整体测试，每个产品只报一组成绩。** 五个被测对象为 OpenViking 0.5.4.1、ai-memory 3.4.7、claude-mem 15.17.0、Basic Memory 1.0.0 + 使用官方 `memory-capture` 的 agent，以及 X2（未公开的内部系统，版本见本轮运行清单）。各自的架构、入库标准、审核流程和默认配置共同构成被测对象。X2 使用 agent 和审核环节当前生效的标准，取审核后的正式页。OpenViking 的全量出口包含原文附件。Basic Memory 由配套 agent 决定写什么，报告注明这一组合。11 月 12 日的旧成绩和运行记录只用于核对历史可跑性及预算。[历史配置](../docs/systems.md)

**统一输入和运行。** 使用固定 revision 与文件 SHA-256，从同一转换器生成 transcript。保留说话人、轮次、工具名和参数、切段点，长工具输出按 v0.6 的 2,000 字符规则截断并标位置。头部记录源会话、日期、cwd、轮数；盲标确认实际项目，记录统一交给系统的头部，禁止私下替个别系统补齐项目名或上下文。超过 300 轮的源按话题或时间切开，同源保留同一聚类键。历史切段直接采用表 1 中的文件。保留适配器实际交付的输入、产品默认跳过或截断事件的计数。

本轮被测 LLM 固定为 `deepseek-v4.1-flash-1017`。各产品保留自己的架构、入库标准、向量功能、提示词、生成参数和审核设置。安装时必须填写且无默认值的项目，采用该产品正常运行所需的最少配置，并在报告标明实值和依据。样本、出题、作答、判分和计量使用统一协议。`default-v2` 与 `halumem-v1` 是裁判判断应记内容的依据，只交给评测侧。每个配置在单轮内各摄取一遍，结论归于产品整体。v0.7 从会话材料重建金标。v0.7.1 复用同批金标、政策和样本，只给公开题面补截点。涉及摄取管线修订的配置按裁定重放，其他配置保留已冻结的写入导出。修改过的题面重答，全组使用新版任务判分。原文和导出均未变化的摄取诊断可复用，重放后的摄取诊断重新判分。报告按当轮口径计分。

## 2　调参集与正式测试集

**两条隔离规则。** ① 调参集和正式测试集分开。被测系统的优化只能依据调参集或真实使用；测试结果、错题和判定理由不得反过来用于调参。Trace 按源会话、HaluMem 按源用户分组，同源切段不跨集。已用于优化的测试来源转入调参集，后续用未见来源比较。② 考生与裁判分开。被测系统只收会话，看不到金标、参考答案、题库或判分提示；裁判侧盲标时看不到产品输出。先定样本、要点、权重和参数，再看结果。一次摄取和判答即可出表，预登记哈希可按审计需要留存。

**调参集封锁清单。** Trace 为 tc01、tc02、tc05、tc06-p2、tc08-p2、tc09-p2、tc09-p3、tc10、tc13-p2、tc14、tc16、tc17，共 12 段、11 个源；同源其余切段均随之隔离。HaluMem 以历史 first30.txt 的实际顺序，封锁 halumem-medium-161e74a81851efb4 的 s0015、s0034，以及 halumem-medium-1e18c8d18b0fa476 的 s0005、s0014、s0030、s0049（前缀与后缀用短横线相连），并封锁这两个用户的其他 session。用完整来源 ID 对照已知调参清单。如 Claude 的 15 条复核另涉及表中来源，也按此规则移出。选样清单和源顺序留在本地运行记录。

## 3　先判应记性，再定所需精度

评测侧对 Trace 使用 default/v2，要求用户或项目独有、已确认或实测、将来可复用；区分 decision、preference、fact、research，按政策校验 basis 和 scope。助手建议、通用文档复述和一次性指令各按原因码进入边界负例 N。HaluMem 使用 halumem/v1，保留官方 Persona / Event / Relationship、memory_source、is_update、importance 和原 point index；单次个人事件和未来计划可以应记。两份政策各自的范围、原因码、条件类型和最终状态规则均生效，各自计分。增加政策仍须同时提供机器枚举、定义、证据要求和切分判例。[default-v2 政策与 JSON 结构](../policies/default-v2.md) · [HaluMem 政策](../policies/halumem-v1.md)

**金标契约。** 每个能独立复用的命题建一个 U，条件随主体。每个 U 有稳定 ID、类别、政策属性、主体 statement、scope、预期复用动作、证据轮次及原文连续引文、uncertain、origin 和裁定理由。涉及秘密时仅引用不含值的片段，必要时以轮次和脱敏定位替代引文。主体、必要条件及细节写入 elements，每个元素有独立 ID、角色、是否必要、所需表示、可接受的等价形式、证据和遗漏后果。沿用条件 type；原 key 的作用由“必要”统一表达。可选背景有据可留，缺失不罚。不得把所有路径、数值和提交号塞回主体。判必要性时问：省略后会不会选错对象、扩大授权、用错时点、丢失行动前提或无法完成指定动作？

| 所需表示 | 判定者验什么 | 同一细节何时会改变要求 |
|---|---|---|
| gist（大意） | 保留对象、方向及对该用途有影响的语义，接受转述 | 只需知道选型从 A 改为 B，能指出变更方向即可；若还问为什么放弃 A，理由另列必要要素 |
| pointer（定位） | 说得出到哪里查、查哪个对象或字段；版本、环境、权限会影响解析时必须说明。出题前用当时可用的证据快照验证唯一定位，冻结可接受引用 | 问如何核实预发布端口，指出对应仓库、分支、配置文件和字段即可。“见配置”或只背出某个端口，均不能完成定位 |
| exact（精确） | 对象、值、否定、时态和限制达到行动所需的精度。唯一可解析的标识、等价单位或不扩大权限的转述可通过；仅当字面形式影响执行或要求逐字引用时才按字面核验 | 问本次立即连哪个端口，需给当时的正确值；“仅 staging 的 sg-02 可启用，生产须另确认”须保留环境、对象和确认条件 |

一项用途可同时需要 locator 和原值，两者拆为两个必要元素。定位正确却附带冲突的现值，标矛盾；清楚标日期且证据支持的历史值可保留。无法确认定位可达、意图或等价关系时标争议，必要时另行复核。不得自动沿 gist、pointer、exact 逐档升格。报告各类的分布、争议率和抽检结果。

**证据与盲法。** 确认以发生轮次为准，后面的表态不能成为早先行动的依据。外部旧上下文不在本段时标 prior_context，单列且不入 U/N。被替换的旧状态在本段结束时按政策进 N，记录其历史时点。N 使用 reject_reason 和 random / targeted，保留证据。HaluMem 从固定 point 清单出发（interference 留在 N），逐个回到对应对话定位具体证据，区分计划、猜测与已发生。复合点可拆成原子 U，保留父点到子 U 的完整映射；原点所有必要子项达标才算父点达标，分别列两种分母，不能把重组结果叫官方得分。

两类数据都由 `gpt-6.2-sol` 重新盲标。Trace 只给 transcript、v0.7 框架和评测政策。HaluMem 额外给数据集原生 memory points 及其元数据，重新定位证据、划分要素并标所需精度。两者均不向标注者提供 v0.6 金标、判定或产品输出。在同一次盲标中生成 coding 题卡；只让标注者看到指定输入，所有引文和历史指令均视作数据。保存金标、题目、参考答案和版本后再揭盲。揭盲发现遗漏建 gold_miss，记 origin=added_by_run:<配置>、修订号及全组复核记录；主分母只取 origin=blind。所有争议项分别给出排除和纳入的召回结果，争议超过该批 U 的 15% 复审政策。

**验证边界属于必要的 exact 语义。** 评的是结论在什么证据下成立。“已写入源码、没有运行验证”“问题仍未解决”“只验证过第一条记录”分别限制验证状态、解决状态和覆盖对象。漏掉其中一项导致证据不足，判 partial；把未运行写成运行通过、把首条写成全量或把未解决写成已解决，判 distorted。等义表述均可。轮号、执行轨迹、验证方法通常是可选细节，金标仍保留轮次以供审计；任务若要求复查，给到可核验的位置可按 pointer 达标。仅当方法或参数决定结论能否复现，才升级为必要元素。易变事实须标原验证日期或有证据的时点，区分验证日、写入日、回放日；材料缺日期则标缺口、要求重查，禁止臆补日期或当作当前事实。范围用用户的问题核验：“换一个项目工作时，agent 不知道这条会不会做错？”会跨项目造成错误的规则或偏好可归 global；个人通用事实归 user，产品专属决定或配置归相应 project。多仓同产品可共享项目范围。

**修订依据。** 用户提供了 Claude 对 X2 正式页的定向模型复核：抽取 Trace 已判 partial 的 15 条，约 7 条丢了可从代码或配置核回的细节（固定窗口 ID、组件序号映射、max-age 精确值、内核配置版本），约 6 条丢了关键内容，其中约一半涉及验证边界，其余包括原始要求的一部分、命令必需参数或“仍未解决”的状态。另 2 条介于两者之间，例如验证仅覆盖首条记录。前一组只是 pointer 候选，仍须检查记忆是否真的能把人带到正确位置。这个分布解释了为什么同判 partial 的两条记忆对下次工作的影响可能不同。它来自单系统、单阶段、按旧标签选取的 15 条，未提供逐条底稿，不作人类校准、总体比例或重新计分依据。独立核对的历史旁证是：提案原选 8 个 Trace 段的 167 个旧 U 中，152 个已有条件，150 个含关键条件；“条件几乎全空”不能推广到 Trace。HaluMem 转换器则直接生成空条件。两者需要分别修正标注。

## 4　价值轴：下次能否做对

四个主场景对应 default-v2 的四种记忆用途。用题目的主要行动目的归类，每题只占一个场景。相同的“已验证事实”在查旧结论时可属 S3，在决定接手后该验什么时可属 S4。S5“不被误导”横跨全部题。本轮四种用途各占 25 分，另按所有有效任务中的可归因记忆误导比例最多扣 10 分。

| 场景 | 一道合格任务应检验什么 | 本轮权重 |
|---|---|---:|
| S1 理解用户 | 面对新选择，能用本人确认的偏好、约束及适用范围作判断，分清谁表达过什么 | 25 |
| S2 解释决策 | 能说清已拍板的选择、影响取舍的理由、放弃的选项，以及重开讨论的条件 | 25 |
| S3 避免重复研究 | 能复用项目独有实测或综合结论，指出已排除的假设、该去哪里核实，以及尚未知的部分 | 25 |
| S4 延续工作 | 能接过一个有后续用途的工作，交代当前状态、已验范围、下一行动或验收缺口 | 25 |
| S5 不被误导 | 答案是否复用了所给记忆中的过期状态、虚构事实、错误归属或扩大的权限，并造成行动错误 | 最高扣 10 分 |

**出题。** 8 段 coding 目标共 24 题，每段原则上 3 题，可在 2–4 题之间调剂，目标每场景 6 题、尽量跨至少 2 个源，题量服从证据。某场景只有 1 个源时标明，完全缺项则不算综合分。HaluMem 只做摄取诊断，不参与 coding 分数。各题只依赖该段独有且政策允许保留的信息，题面不泄露答案。题库覆盖定位、执行建议、范围限制、验证边界、冲突和带理由的安全暂缓。每题冻结 task_id、评估时点、主场景、关联 U/element ID、必答要点、禁止推出的结论、可接受等价、证据、预期动作和严重错误条件。题卡有 Tn 截点时，公开题面须明确写出「以 Tn 时的状态为准」。定位题答出“去哪查什么”即可；要求给出执行值的题，只有路径不能成功。缺口题必须指出具体未知项及合理核验动作，通用“无法确定”不得分。

**作答。** 作答使用 qwen4-max，生成参数沿用端点默认。所有评测配置共用同一作答型号、请求参数和窗口，记录实际型号或快照。每题独立上下文，只见题目和全部 D，禁工具及外查。按原生导出顺序编号，保留真实可见的范围/来源，隐藏产品身份。超出固定窗口记 reader_overflow 和所需 token，禁止静默裁短。

**判题。** 同一系统同一段的约 3 个独立答案可合成一次裁判请求，各题仍按 task_id 独立判。裁判读匿名答案、题卡和所用 D，记录逐要点支持/缺失/冲突、memory_id 与结果（全对、部分、具体弃答、答错）。要点支持分别计量。全部必要点正确且无行动错误才计全对，全对率仅作为诊断。确有泄题、属通识或证据缺失的题对全组统一撤销并列出原因和分母。

**行动错误与归因。** `action_error` 成立的情形为把材料没有的条件说成既定事实或硬门槛，或给出的当前行动会把事情做错。附条件的后续建议、可选核验和「若要……可以……」本身不计。行动错误率单独报告，各个已成立的要点保留。记忆归因要求对象、时点和范围相同，并有实际复用证据。空库仍可有行动错误，记忆归因记零。本轮保留裁判提示和判分回执，最终复算从已有回执的 `misleading` 字段读取记忆归因。

**价值分。** 每题得分为成立要点数除以必答要点数，缺失或矛盾的点得零分。p₁…p₄ 为各场景有效题得分的均值，每题等权。m 为全测试有效题中 `misleading=true` 的比例，每题至多记一次。V = max(0, 25 × (p₁+p₂+p₃+p₄) − 10m)。另列全对率、按要点汇总的完成率和风险诊断。

## 5　效率轴与综合分

按片段提炼能让下次会话少读材料。全量存档在价值轴可以答对；它要求读者重读的每一个 token 也进入效率轴。写入时大量反复读 T、重试、整理、审核均会影响资源开销。采用提案 §13 的对数扣分，效率以实际用量及扣掉的价值百分点表达。

对每个 coding 段 i 记录三笔量。Tᵢ 为冻结 transcript 的 token 数。Rᵢ 为各有效作答实际收到的记忆部分 token 的段内均值，包含原文附件、读者可见的范围和包装，共同指令与题面另列。T 与 R 使用同一版 tiktoken 的 `o200k_base`。Wᵢ 为从空库到冻结导出期间，写入端点在 `usage.prompt_tokens` 返回的输入用量总和，包含 agent、审核与纠错请求，每个请求计一次。Bᵢ = Wᵢ/Tᵢ。W 是供应商计量，T 与 R 是统一 tokenizer 计量，B 是跨 tokenizer 的扣分口径。没有写入模型调用时 Wᵢ=0。缺少实际请求用量时记 NA。写入输出、嵌入、调用数、延时、跳过、缓存用量、读者实际用量和判分用量另列。回放中的重复阅读照计。

令 L(x)=0（0≤x≤1），x>1 时取 log₂(x)。正式分采用中档汇率：r₀=0.05、w₀=1、a=4、b=2.5。每段读扣分 Pᵣᵢ=a·L(Rᵢ/(r₀Tᵢ))，写扣分 P𝓌ᵢ=b·L(Bᵢ/w₀)。先逐段扣分再对参与价值分的 coding 段等权取均值。整段超窗时保守全对率照计失败，综合分使用有有效任务判定的段。**综合分 C=max(0,V−mean(Pᵣᵢ)−mean(P𝓌ᵢ))**，同时显示未截底余量、两笔扣分和绝对 token/题、token/段的中位数、均值与最大值。T 必须为正，成功空库 R=0，W 按实计；缺用量写 NA，禁止把未记录填成 0。输出很长、模型单价、缓存折扣和向量开销仍需在账本里读，本分数没有货币单位。

举例：若价值同为 80，R/T=5%、B=1 时得 80；R/T=100%、W=0 时读扣 17.29 分，得 62.71；R/T=5%、B=16 时写扣 10 分，得 70。真实全文保留仍可凭价值优势领先，报告须让读者看见多读多少才换来这些成功。**公开报告必须给出九格敏感性结果。** 对每个产品，用同一批答案和用量按 a∈{2,4,6}、b∈{1,2.5,4} 的笛卡尔积重算综合分。以 a 为行、b 为列列出全部九格，标出主结果 (4, 2.5)，并说明哪些产品间的差值改变符号或出现并列。只需离线算分，无需重复调用模型。原报告 0.72 是文本长度比，16.7 的表头是输入 token / transcript **字符**，不能当新公式的 token 比率。以上例子均为假设值。[11 月 12 日报告 §3–4](../reports/2026-11-12/README.md)

## 6　摄取诊断与范围

1. **召回。** 将每个盲标 U 的必要元素、用途、scope、等价及定位合同交 judge，对照同段全量 D；不提供原会话给 judge 补全。记录每元素支持、缺失、矛盾或不可核验，以及最短证据与 memory_id。只可联合相同对象/范围/时点的文字。全部必要元素满足为 full；有支持但缺必要元素为 partial；无相关证据为 none；相关证据明确改变结论且无完整正确支持为 distorted（优先于 partial）。正确与错误并存且有完整支持时仍判 full，另记冲突供精确与任务评测。金标本身无法核证走 uncertain；候选仅泛指“见配置”属于定位缺失。主漏记率=(partial+none+distorted)/盲标确定 U；分列四档、none+distorted、必要元素缺失、争议全纳入后的率。后置报相同新 U 上“含可选细节的逐字完整率”，单独标新严格诊断；它与 v0.6 允许省略次要条件的规则有不同含义。
2. **精确。** 每条 D 对照 T 和政策拆成可核验原子陈述。互斥优先级为 distorted > unsupported > partial > supported。证据指对象 A 却写成 B 属写歪；本无编号却加编号按核心有无依据判 partial 或 unsupported；可验证的等价短标识可通过。判断事实时区分说话人、验证时点与写入日期。原样摘录整块核对并记 1 个陈述，摘要照常拆。Trace 的整段聊天照搬按 default-v2 标记 `verbatim_chat`；其中有依据的事实仍按真实性判定，实际读取量计入成本。只摘必要命令、结论或证据短句不触发该标记。错记率=(unsupported+distorted)/全部 claims。另报 partial、与错记合计的依据不足或错误率、摘录占比和长度、去摘录正文的错记率、每段条目/claims 数。整条 worth=yes/no/unclear，政策不值得记占比=no/全部条目；不以条目包装惩罚混合页两次。U、D 或 claims 的分母为零记 NA；U=0 段仍计 D。保留每条错误的脱敏定位，本地错误摘要可限十例但计数须完整。
3. **风险和范围。** 核真实正文、原生项目命名空间和项目/用户身份；报告应判项中有证据可判的比例，以及可判项准确率。缺范围信号标不可判，不能从 gold 补答案。检查扩大授权、旧结论当现状、相互冲突、验证边界、必需定位的定位成功率与来源可追溯率。按政策分别报误收 N 的比例（被命中的不同 N / N）、外部上下文与重复例。拆分协议不从 claims 推算单元 F1 或全库重复率。标识符冲突和秘密值标记在独立维度处理。default-v2 禁存秘密值，即使事实有据也须标红。金标排除秘密值，示例及错误明细仅给脱敏定位。
v0.6 的原金标和判定仅作历史资料。即便 transcript、产品或导出内容相同，也须使用 v0.7 新金标重新判分。上文的逐字完整率只描述本轮细节保留情况。[v0.6 框架](framework-v0.6.md)

## 7　一次运行如何出报告

**分母和失败。** 先报每个产品在固定清单的完成数，分开摄取失败、成功空库、审核未完成、输出超窗、判定失败和缺计量。全产品都有效的同一批段用于配对比较，标交集大小；同时报全测试集的覆盖率和把产品实际不可用计为任务失败的保守成功率。评测服务故障记未测。四个场景齐备、读写用量完整才给对应样本集的综合分，注明全测试集或共同子集。有效空库正常作答，分母为零的率写 NA。

**统计。** 同政策内按分子分母相加计算漏记和错记，场景内按题汇总。每个分项报题数、样本数、独立来源数。沿用按 gold.session_id 聚类的 10,000 次 bootstrap，seed 20261112，取 95% 百分位区间。系统差使用相同的源抽样次数，重算双方的价值、成本和综合分再相减。缺场景或零分母的重抽记无定义，报有效次数；单簇只展示个例。以上均用本轮已有结果离线计算。按轮长报告三个层次，HaluMem 的四个用户只作方向性描述。

**报告和复算。** 第一页列隐私命中、完成数、综合分、四个场景与误导率，再列每段读写 token 和扣分、召回/错记原因。公开附上 §5 的九格敏感性结果。列明标注/判分者是人还是模型、是否做过人类校准、各产品版本与阶段、实际参数、样本 ID、政策及缺失。留存本地 T、gold、题卡、D、答案、judgments 和用量，足以原样复算；需要审计时再附哈希及完整环境。只在调参集把题级错误交给优化者。Trace 加工产物按 CC-BY 署名并脱敏，HaluMem 对外仅发分数与哈希，私有会话留本地。未做人工核验直写“模型判定，未做人类校准”，可正常出本轮分数。[数据清单](../datasets/README.md)

**实现与回执。** 每轮使用独立产物目录。冻结输入、判分及复算阶段校验 ID、引用轮次与哈希，按 §1 记录模型和推理档位。[模型提示](../tools/model/prompts/) · [本版评分器](../tools/model/v07/scoring.py)

## 8　主轮的调用预算

按表 1 补齐 12 段、五个产品各一次回放、8 段 coding 共 24 题估算。每段一次盲标，coding 同次生成题目和要点。所有答案逐题独立作答；判分可合批，确保每个 task_id、unit_id 或 memory_id 恰好返回一次。HaluMem 只做摄取诊断。以下只计公开主轮。

| 类别 | 调用方式 | 预计请求 |
|---|---|---:|
| 标注及出题 | 8 段 Trace + 4 段 HaluMem 各一次 | **12** |
| 作答 | 24 题 × 5 产品 | **120** |
| 任务判分 | 每个 coding 段、每个产品一次，批内逐题给分 | 40 |
| 召回判分 | Σ产品 Σ段 ceil(Uᵢ/30)，预算假设每段 1–30 U；每批含全量 D | 约 60 |
| 精确判分 | Σ产品 Σ段 ceil(Dᵢ/30)，空 D 用 0。8 个历史共同样本中，Basic Memory、claude-mem 和 OpenViking 按旧 D 实算 32 批；同 8 段为 ai-memory 新版和 X2 估 16 批。其余 4 段暂按每段五产品合计 6 批预留 | 约 72 |
| **判分小计** | 任务 40 + 召回 60 + 精确 72 | **约 172** |

**总计约 304 次评测模型请求，外加 60 个产品摄取作业。** 摄取作业可能触发多次 LLM 调用，逐次计入写入账；没有实测前不能换算为金额。若只跑目前四家已通过的 4 个 coding 源与 4 个 HaluMem 用户，按每 coding 段 3 题，预算为标注 8、作答 60、任务判分 20、召回约 40、精确约 48，共约 176 次；报告必须标出覆盖缺口。实际新 U、新 D、拆批或重试会改变次数。评测用量与产品成本分账。

## 9　提案 §12、§13 在本轮的处理

主轮利用一次运行已有的材料检查时效、范围、隐私和可追溯性。旧结论带日期保留可作为历史，把它当成现状按 §6 判定。有范围证据的记忆报准确率，缺证据的报不可判。秘密暴露查正文、附件和读者可见元数据，在报告开头标红，报告只留脱敏位置。有出处和能据此定位分别计数。样本盲标确属 U=0 时照常记录空库率及误收情况。

每个产品、每个样本只跑一次，因此本轮无法估计运行波动、跨段更新效果或专门构造输入时的泄露率。公开报告直接给出绝对价值分与同样本产品间的配对差。§5 的九种汇率组合使用同一批用量与答案，公开时同时呈现。

## 附录　独立审阅的取舍

- 采用可核证的定位、接受等价的 exact、基于预期用途的必要元素、官方 point 与原子单元的独立分母，以及同源配对和失败分解。旧 `recoverable` 与 `core` 档由新规则替代。pointer 占比高只提示复查。
- 保留全量 D 和实际读写开销。统一截断会改变产品交给下次会话的内容；公开主轮因此读取真实出口并记录超窗。产品之间的差异反映架构、原生标准与配置共同带来的效果。
- 采用四种实际用途和横跨场景的误导扣分。按条统计的 worth 容易受包装粒度影响，留作诊断。小样本报告源数、区间与校准状态。既有材料已能支持评分和复算，提案中需要新增实验组或重复运行的建议不纳入公开方案。
